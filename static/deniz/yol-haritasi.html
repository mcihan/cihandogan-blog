Nerede duruyorsun

Durum tespiti · neyin var, neyin yok

Scrum Master geçmişin burada küçük bir detay değil: birçok QA adayında olmayan şey sende var — süreci, refinement'ı, kabul kriterini, paydaşla konuşmayı biliyorsun. ISTQB de o dili resmîleştirdi. Eksik olan tek şey elle iş yapabilme kanıtı.

Acı gerçek: saf “manuel QA tester” ilanları daralıyor. 2026 ilanlarında junior seviyede bile Playwright/Selenium, API otomasyonu, CI/CD ve SQL standart hâle geldi. Hedefin manuel tester değil, “otomasyon da yazabilen QA engineer” olmalı. Java'yı zaten biliyorsun — yolun yarısındasın.

✅ Elinde olan

Scrum/agile süreci · ISTQB CTFL · Java ve Python temelleri (sınıf seviyesi) · paydaş iletişimi · kabul kriteri yazma · DoD/DoR

SQL · API testi · bir otomasyon çatısı · Git/CI · Linux temelleri · ve en önemlisi: gösterebileceğin bir repo

QA Engineer · Test Engineer · QA Automation Engineer (Junior) · SDET (Junior). “Agile ekipte QA” arayan yerlerde avantajlısın.

5

Tam plan — Faz 2

API testi · 3–4 hafta · en yüksek getiri

Burası UI otomasyonundan hem daha kolay hem işe girerken daha çok işine yarıyor. En yüksek getirili faz bu.

  1. Postman
    Koleksiyon, environment, değişken, pm.test() ile assertion, Newman ile komut satırından koşma.
  2. RestAssured (Java)
    given/when/then, JSON path ile doğrulama, POJO serileştirme, kimlik doğrulama.
  3. JUnit 5
    Assertion, test yaşam döngüsü, @ParameterizedTest — sınır değer testlerini parametrik yazmak tam buraya oturuyor.
  4. Maven
    Bağımlılık yönetimi, mvn test, profiller, raporlama eklentileri.

Çalışma hedefi

Açık bir API'ye ya da kendi yazdığın küçük servise 15–20 testlik bir paket. CRUD + negatif senaryolar + şema doğrulama. Testler GitHub'da dursun.

Tam plan — Faz 3

UI otomasyonu · 4–5 hafta

Playwright (Java) ile başla — Selenium'dan daha az kırılgan, auto-wait'i var, öğrenmesi hızlı. Sonra Selenium'a 1 hafta ayır; ilanların çoğunda hâlâ adı geçiyor, syntax farkı küçük.

Öğrenecekler

Locator stratejisi (CSS / XPath / role) · Page Object Model · bekleme mantığı · test verisi yönetimi · paralel koşum · ekran görüntüsü ve trace ile hata ayıklama

Playwright mi Selenium mu

Öğrenirken Playwright — daha az kodla daha sağlam test. CV'de ikisi de — ilan filtreleri hâlâ Selenium'a bakıyor.

Tuzak

50 senaryo yazma. 10 sağlam, kırılmayan senaryo yaz. Mülakatta “flaky testleri nasıl çözdün?” sorusunun cevabı tam olarak buradan gelir — 50 tane kırık testten gelmez.

Portföy

İşe alan kişi buraya 5 dakika bakıyor

İşe alan kişi sertifikaya 5 saniye, GitHub'a 5 dakika bakıyor. Tek bir repo yeter — ama gerçek olsun.

qa-framework/
├── api/          RestAssured + JUnit 5, 15–20 test
├── ui/           Playwright + Page Object, 10 test
├── .github/      Actions pipeline, Allure raporu
└── README.md     mimari kararları, nasıl koşulur, ne kapsıyor

README'de ne yazacaksın

Kod kalitesinden çok karar gerekçeleri konuşuluyor:

  • “Neden Page Object kullandım, alternatifi neydi”
  • “Şu test flaky'ydi, nedeni şuydu, böyle stabilize ettim”
  • “Hangi senaryoyu bilerek otomatikleştirmedim, neden”
  • “Test verisini nasıl yönetiyorum”

Son madde özellikle önemli: neyi otomatikleştirmediğini gerekçelendirebilen aday, ISTQB'yi ezberlemiş değil anlamış demektir.

Mülakat

Ne soruluyor, senin kozun ne
Ne sorulurNasıl hazırlanırsın
SQL sorusuTahtada JOIN yazdırırlar. En sık eleme burası. 20 sorgu çöz, ezberden değil yazarak.
Test tasarımı“Şu ekranı nasıl test edersin”, sınır değer, denklik payı. ISTQB'den geldiğin için güçlüsün — konu sayfalarına dön.
Hata raporuEksik bir rapor verip “ne eksik” diye sorarlar. Ortam, sürüm, veri, adımlar — bu konuyu zaten çalıştın.
KodString/dizi seviyesi basit bir soru. Java'da yazabilmen yeter, algoritma yarışması değil.
Çatı sorusu“Page Object nedir, neden”, “flaky test nasıl çözülür”, “neyi otomatikleştirmezsin”.

Senin kozun

“Scrum Master'ken test sürecini nasıl kurardım” sorusuna gerçek cevabın var: shift-left, three amigos, DoD'a test kriteri koyma, refinement'ta test edilebilirlik sorgulama. Bunları yaşamışsın. Anlatan 100 adaydan 95'i anlatamıyor — bu senin en büyük farkın, mülakatta mutlaka aç.

Yapma

“Scrum Master'dım ama kod yazmak istiyorum” deme — kaçış gibi duyuluyor. “Süreci içeriden biliyorum, şimdi kaliteyi ölçen tarafta olmak istiyorum” de. Aynı geçmiş, tamamen farklı izlenim.
