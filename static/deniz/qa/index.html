01

What is a REST API?REST API nedir?

An API is a way for two programs to talk to each other. One program asks, the other answers. The one that asks is the client (a website, a mobile app, Postman). The one that answers is the server.API, iki programın birbiriyle konuşma yoludur. Biri sorar, diğeri cevap verir. Soran taraf client'tır (bir web sitesi, mobil uygulama, Postman). Cevap veren taraf server'dır.

Think of a restaurant. You are the client. The kitchen is the server. The waiter is the API: you give your order to the waiter, and the waiter brings back the food. You never go into the kitchen.Bir restoran düşün. Sen client'sın. Mutfak server'dır. Garson ise API'dir: siparişi garsona verirsin, garson yemeği getirir. Mutfağa hiç girmezsin.

REST is a set of rules for building APIs on top of HTTP, the same protocol your browser uses. The main ideas:REST, API'leri HTTP üzerine kurmak için bir kurallar bütünüdür. HTTP, tarayıcının da kullandığı protokoldür. Ana fikirler:

  • Everything is a resource with its own address (URL): users, products, orders.Her şey kendi adresi (URL) olan bir resource'tur: kullanıcılar, ürünler, siparişler.
  • You use HTTP methods (GET, POST, PUT...) to say what you want to do with the resource.Resource ile ne yapmak istediğini HTTP metotlarıyla (GET, POST, PUT...) söylersin.
  • Data is usually sent as JSON.Veri genellikle JSON olarak gönderilir.
  • The server is stateless: it does not remember you between requests. Every request must carry everything the server needs. This is why tokens exist (see lesson 8).Server stateless'tır: istekler arasında seni hatırlamaz. Her istek, server'ın ihtiyaç duyduğu her şeyi taşımalıdır. Token'lar bu yüzden var (bkz. ders 8).
02

What is inside a request and a response?Bir istek ve cevabın içinde ne var?

A request has four parts: the method, the URL, the headers and (sometimes) the body.Bir isteğin dört parçası vardır: metot, URL, header'lar ve (bazen) body.

POST https://api.shop.com/users/login        ← method + URL
Content-Type: application/json               ← header
Accept: application/json                     ← header

{                                            ← body
  "email": "cihan@test.com",
  "password": "MyPass123"
}

A response has three parts: the status code, the headers and the body.Bir cevabın üç parçası vardır: status code, header'lar ve body.

200 OK                                       ← status code
Content-Type: application/json               ← header

{                                            ← body
  "token": "eyJhbGciOi..."
}

With PUT, if you forget a field, the server may delete it or return an error. This is a good thing to test.PUT'ta bir alanı unutursan server onu silebilir veya hata dönebilir. Bu, test etmek için iyi bir konudur.

05

Headers: what they are and why we need themHeader'lar: nedir ve neden ihtiyaç duyulur

A header is a small piece of extra information, written as Name: value. Headers are not the data itself. They describe the request or the response.Header, İsim: değer şeklinde yazılan küçük bir ek bilgidir. Header'lar verinin kendisi değildir. İsteği veya cevabı tarif ederler.

Think of a letter. The body is the paper inside. The headers are what is written on the envelope: who sent it, what kind of paper is inside, how to handle it. The post office reads the envelope first.Bir mektup düşün. Body, içindeki kâğıttır. Header'lar zarfın üstünde yazanlardır: kim gönderdi, içinde ne tür bir kâğıt var, nasıl işlenmeli. Postane önce zarfı okur.

Why do we need them?Neden ihtiyaç duyulur?

  • The server must know who you are on every request, because it does not remember you.Server her istekte kim olduğunu bilmelidir, çünkü seni hatırlamaz.
  • The server must know what format the body is in, so it can read it.Server body'nin hangi formatta olduğunu bilmelidir ki okuyabilsin.
  • This information is the same kind for every endpoint, so it has one standard place. It does not belong in the URL or the body.Bu bilgi her endpoint için aynı türdendir, bu yüzden tek bir standart yeri vardır. URL'e veya body'ye ait değildir.
  • Secrets like tokens should not be in the URL, because URLs are saved in browser history and server logs.Token gibi gizli bilgiler URL'de olmamalıdır, çünkü URL'ler tarayıcı geçmişine ve server loglarına kaydedilir.

06

The body and JSONBody ve JSON

JSON is a simple text format. It has names and values. You already know it from Python: it looks like a dictionary.JSON basit bir metin formatıdır. İsimler ve değerlerden oluşur. Python'dan zaten biliyorsun: dictionary'ye benzer.

{
  "firstName": "Ali",          ← text (string)
  "age": 31,                   ← number
  "active": true,              ← true / false (boolean)
  "middleName": null,          ← empty (null)
  "phones": [                  ← list (array)
    "0712",
    "0798"
  ],
  "address": {                 ← object inside an object
    "city": "London"
  }

Rules: names are always in double quotes. Text values are in double quotes. Numbers, true, false and null are not. No comma after the last item.Kurallar: isimler her zaman çift tırnak içindedir. Metin değerleri çift tırnak içindedir. Sayılar, true, false ve null değildir. Son elemandan sonra virgül olmaz.

08

Login: how the server knows who you areLogin: server kim olduğunu nasıl bilir

The server forgets you after every request. So you must prove who you are each time. Sending your password every time is not safe. The usual way is: log in once, get a token, and send the token with every request after that.Server her istekten sonra seni unutur. Bu yüzden her seferinde kim olduğunu kanıtlamalısın. Her seferinde şifre göndermek güvenli değildir. Yaygın yol şudur: bir kez login ol, bir token al ve sonraki her istekte token'ı gönder.

  1. You send your email and password to the login endpoint.E-posta ve şifreni login endpoint'ine gönderirsin.
  2. The server checks them and sends back a token.Server bunları kontrol eder ve bir token döner.
  3. You save the token (in Postman: in a variable).Token'ı kaydedersin (Postman'de: bir variable'a).
  4. You add the token to the Authorization header of every next request.Token'ı sonraki her isteğin Authorization header'ına eklersin.
  5. When the token expires you get 401. You log in again or use a refresh token.Token'ın süresi dolunca 401 alırsın. Tekrar login olursun veya refresh token kullanırsın.

09

JWT: what it is, what is inside, why we use itJWT: nedir, içinde ne var, neden kullanılır

JWT means JSON Web Token (people say "jot"). It is a long piece of text that the server gives you after login. It is like a signed entry ticket: it says who you are and until when it is valid, and the signature shows nobody has changed it.JWT, JSON Web Token demektir ("cot" diye okunur). Login'den sonra server'ın verdiği uzun bir metindir. İmzalı bir giriş bileti gibidir: kim olduğunu ve ne zamana kadar geçerli olduğunu söyler, imza da kimsenin onu değiştirmediğini gösterir.

Three parts, separated by dotsNokta ile ayrılmış üç parça

PartParçaWhat is insideİçinde ne var
1. HeaderThe type of token and the signing method, for example { "alg": "HS256", "typ": "JWT" }.Token türü ve imzalama yöntemi, örneğin { "alg": "HS256", "typ": "JWT" }.
2. PayloadThe information about you. These are called "claims".Senin hakkındaki bilgiler. Bunlara "claim" denir.
3. SignatureA code the server makes from parts 1 and 2 plus a secret key that only the server knows.Server'ın 1. ve 2. parçadan ve sadece kendisinin bildiği gizli bir anahtardan ürettiği kod.

A typical payloadTipik bir payload

{
  "sub": "42",              ← subject: the user id
  "email": "cihan@test.com",
  "role": "user",           ← what the user may do
  "iat": 1794300000,        ← issued at: when it was created
  "exp": 1794303600         ← expires: when it stops working
}

iat and exp are times written as seconds since 1970. In this example the token lives for 3600 seconds, which is 1 hour.iat ve exp, 1970'ten bu yana saniye olarak yazılmış zamanlardır. Bu örnekte token 3600 saniye, yani 1 saat yaşar.

Why do we use it?Neden kullanılır?

  • The server does not need to store sessions. Everything it needs is inside the token. It only checks the signature.Server'ın oturum saklamasına gerek kalmaz. İhtiyacı olan her şey token'ın içindedir. Sadece imzayı kontrol eder.
  • It cannot be changed. If someone edits the payload (for example "role": "admin"), the signature no longer matches and the server rejects it with 401.Değiştirilemez. Biri payload'ı düzenlerse (örneğin "role": "admin"), imza artık uymaz ve server 401 ile reddeder.
  • It works across many servers and services. Any service that knows the key can check the token.Birçok server ve serviste çalışır. Anahtarı bilen her servis token'ı kontrol edebilir.
  • It expires by itself. A stolen token is only useful for a short time.Kendi kendine sona erer. Çalınan bir token sadece kısa bir süre işe yarar.

Important: a JWT is signed, not hidden. Anyone can read the header and payload. Paste a token into jwt.io and you will see them. So a JWT must never contain a password or other secret data.Önemli: JWT imzalıdır, gizli değildir. Header ve payload'ı herkes okuyabilir. Bir token'ı jwt.io'ya yapıştırırsan görürsün. Bu yüzden JWT içinde asla şifre veya başka gizli veri olmamalıdır.

Access token and refresh tokenAccess token ve refresh token

Many APIs give you two tokens. The access token lives a short time (minutes) and is sent with every request. The refresh token lives longer (days) and is only used to get a new access token without logging in again.Birçok API iki token verir. Access token kısa yaşar (dakikalar) ve her istekle gönderilir. Refresh token daha uzun yaşar (günler) ve sadece tekrar login olmadan yeni bir access token almak için kullanılır.

01

SELECT, ORDER BY, LIMIT, DISTINCT

SELECT picks columns. ORDER BY sorts. LIMIT cuts the list. DISTINCT removes repeated values.SELECT sütunları seçer. ORDER BY sıralar. LIMIT listeyi keser. DISTINCT tekrar eden değerleri kaldırır.

SELECT name, city
FROM customers
ORDER BY name ASC        -- ASC = A to Z, DESC = Z to A
LIMIT 3;

SELECT DISTINCT city     -- London, Leeds, Bristol (London only once)
FROM customers;
02

WHERE and its filtersWHERE ve filtreleri

SELECT * FROM orders
WHERE status = 'paid' AND amount >= 100;      -- both must be true

SELECT * FROM customers
WHERE city IN ('London', 'Leeds');            -- one of a list

SELECT * FROM orders
WHERE amount BETWEEN 50 AND 120;              -- 50 and 120 are included

SELECT * FROM customers
WHERE name LIKE 'A%';                         -- starts with A

SELECT * FROM customers
WHERE city IS NULL;                           -- empty value

Easy to forget: NULL is never equal to anything. = NULL finds nothing. Always write IS NULL or IS NOT NULL. In LIKE, % means any text and _ means one character.Kolay unutulur: NULL hiçbir şeye eşit değildir. = NULL hiçbir şey bulmaz. Her zaman IS NULL veya IS NOT NULL yaz. LIKE içinde % herhangi bir metin, _ tek bir karakter demektir.

03

COUNT, SUM, GROUP BY, HAVINGCOUNT, SUM, GROUP BY, HAVING

COUNT, SUM, AVG, MIN and MAX turn many rows into one number. GROUP BY gives one number for each group. HAVING filters the groups.COUNT, SUM, AVG, MIN ve MAX birçok satırı tek bir sayıya çevirir. GROUP BY her grup için bir sayı verir. HAVING grupları filtreler.

SELECT COUNT(*) FROM orders;                  -- 5

SELECT customer_id,
       COUNT(*)    AS order_count,
       SUM(amount) AS total
FROM orders
WHERE status = 'paid'            -- filters rows, before grouping
GROUP BY customer_id
HAVING SUM(amount) > 100;        -- filters groups, after grouping

WHERE or HAVING? WHERE works on rows and cannot use COUNT or SUM. HAVING works on groups and can.WHERE mi HAVING mi? WHERE satırlar üzerinde çalışır ve COUNT veya SUM kullanamaz. HAVING gruplar üzerinde çalışır ve kullanabilir.

04

JOIN

A JOIN puts two tables side by side using a shared value. Here: customers.id = orders.customer_id.JOIN, iki tabloyu ortak bir değer üzerinden yan yana getirir. Burada: customers.id = orders.customer_id.

SELECT c.name, o.id, o.amount
FROM customers c
INNER JOIN orders o ON o.customer_id = c.id;
JOINWhat you getNe gelirWith our dataBizim veriyle
INNER JOINOnly rows that match in both tables.Sadece iki tabloda da eşleşen satırlar.4 rows. No Maria, no order 105.4 satır. Maria yok, 105 numaralı sipariş yok.
LEFT JOINAll rows from the left table. Empty (NULL) where the right has no match.Sol tablonun tüm satırları. Sağda eşleşme yoksa boş (NULL).5 rows. Maria is there with NULL order.5 satır. Maria NULL siparişle gelir.
RIGHT JOINAll rows from the right table. Empty where the left has no match.Sağ tablonun tüm satırları. Solda eşleşme yoksa boş.5 rows. Order 105 is there with NULL name.5 satır. 105 numaralı sipariş NULL isimle gelir.
FULL JOINAll rows from both tables.İki tablonun da tüm satırları.6 rows. Maria and order 105 are both there.6 satır. Maria da 105 de gelir.

-- customers who have no orders  →  Maria
SELECT c.name
FROM customers c
LEFT JOIN orders o ON o.customer_id = c.id
WHERE o.id IS NULL;
05

SubqueriesSubquery'ler

A subquery is a query inside another query. The inner one runs first.Subquery, başka bir sorgunun içindeki sorgudur. İçteki önce çalışır.

-- customers who have a paid order
SELECT name FROM customers
WHERE id IN (SELECT customer_id FROM orders WHERE status = 'paid');

-- orders bigger than the average order
SELECT * FROM orders
WHERE amount > (SELECT AVG(amount) FROM orders);

-- the same idea as IN, written with EXISTS
SELECT name FROM customers c
WHERE EXISTS (SELECT 1 FROM orders o WHERE o.customer_id = c.id);
06

CASE WHEN

CASE is the if / else of SQL. It makes a new column from a rule.CASE, SQL'in if / else'idir. Bir kurala göre yeni bir sütun üretir.

SELECT id, amount,
       CASE
         WHEN amount >= 150 THEN 'big'
         WHEN amount >= 80  THEN 'medium'
         ELSE 'small'
       END AS size
FROM orders;
07

INSERT, UPDATE, DELETE

INSERT INTO customers (id, name, city)
VALUES (5, 'Sara', 'Leeds');

UPDATE orders
SET status = 'paid'
WHERE id = 103;

DELETE FROM orders
WHERE id = 105;

Never forget the WHERE. UPDATE or DELETE without WHERE changes every row in the table. Run a SELECT with the same WHERE first to see which rows you will touch.WHERE'i asla unutma. WHERE olmadan UPDATE veya DELETE tablodaki her satırı değiştirir. Önce aynı WHERE ile bir SELECT çalıştır ve hangi satırlara dokunacağını gör.

08

The order SQL really runs inSQL'in gerçek çalışma sırası

You write SELECT first, but the database does not start there. This order explains many errors.SELECT'i ilk sen yazarsın, ama veritabanı oradan başlamaz. Bu sıra birçok hatayı açıklar.

1 FROM / JOIN   get the tables
2 WHERE         filter rows
3 GROUP BY      make groups
4 HAVING        filter groups
5 SELECT        pick columns, give names (AS)
6 ORDER BY      sort
7 LIMIT         cut the list

This is why you cannot use a name made with AS inside WHERE (step 2 comes before step 5), but you can use it in ORDER BY.Bu yüzden AS ile verilen bir ismi WHERE içinde kullanamazsın (2. adım 5. adımdan önce gelir), ama ORDER BY içinde kullanabilirsin.

09

Window functions: the basicsWindow function'lar: temeller

GROUP BY squeezes rows into one row for each group. A window function keeps every row and adds a number next to it.GROUP BY satırları her grup için tek satıra sıkıştırır. Window function her satırı tutar ve yanına bir sayı ekler.

SELECT id, customer_id, amount,
       ROW_NUMBER() OVER (PARTITION BY customer_id ORDER BY amount DESC) AS rn,
       SUM(amount)  OVER (PARTITION BY customer_id) AS customer_total
FROM orders;

PARTITION BY is the group. ORDER BY inside OVER is the order inside each group. Here rn = 1 is each customer's biggest order.PARTITION BY gruptur. OVER içindeki ORDER BY her grubun içindeki sıradır. Burada rn = 1 her müşterinin en büyük siparişidir.

QuestionSoruShort answerKısa cevap
WHERE vs HAVINGWHERE filters rows before grouping. HAVING filters groups after grouping.WHERE gruplamadan önce satırları filtreler. HAVING gruplamadan sonra grupları filtreler.
INNER vs LEFT JOININNER returns only matches. LEFT returns all left rows, with NULL where there is no match.INNER sadece eşleşenleri döner. LEFT sol tablonun tüm satırlarını döner, eşleşme yoksa NULL ile.
UNION vs UNION ALLBoth stack two results. UNION removes duplicates. UNION ALL keeps them and is faster.İkisi de iki sonucu alt alta koyar. UNION tekrarları siler. UNION ALL tutar ve daha hızlıdır.
DELETE vs TRUNCATE vs DROPDELETE removes chosen rows. TRUNCATE removes all rows and keeps the table. DROP removes the table itself.DELETE seçilen satırları siler. TRUNCATE tüm satırları siler, tabloyu tutar. DROP tablonun kendisini siler.
Primary vs foreign keyA primary key identifies each row in its own table (unique, not NULL). A foreign key points to a primary key in another table.Primary key kendi tablosundaki her satırı tanımlar (benzersiz, NULL olamaz). Foreign key başka bir tablodaki primary key'e işaret eder.
COUNT(*) vs COUNT(col)COUNT(*) counts all rows. COUNT(col) skips rows where that column is NULL.COUNT(*) tüm satırları sayar. COUNT(col) o sütunun NULL olduğu satırları atlar.

Small differences exist between databases. For example, SQL Server uses TOP 3 where MySQL and PostgreSQL use LIMIT 3, and MySQL has no FULL JOIN.Veritabanları arasında küçük farklar vardır.
